# Code Review

对代码改动做一次完整审查：多角度扫描 → 关键候选验证 → 按严重度报告。

## 何时使用

- "review 一下这段代码/这个提交"
- 循环工作流（review-fix-verify）中的审查步骤

## 工作流

1. **明确范围**：diff、提交、文件或函数
2. **多角度扫描**（独立视角并行）：
   - 正确性：错误条件、null 解引用、缺 await、边界
   - 并发与竞态：check-then-act、锁范围、时序
   - 错误恢复：失败路径、回退、重试
   - 安全边界：注入、权限、敏感信息
   - 清理：复用、简化、实现深度、约定
3. **验证关键候选**：对可疑点读上下文/跑命令确认，区分 CONFIRMED / PLAUSIBLE / REFUTED
4. **按严重度报告**：正确性 > 并发/恢复 > 边界 > 清理，每条含位置 + 触发场景 + 修复方向

## 输出规范

- 每条发现必须能指出**具体代码位置和触发条件**，没有证据的疑点单独标注
- 无问题时明确写"未发现问题" + 未覆盖的风险
