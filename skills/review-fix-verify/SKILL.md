# Review-Fix-Verify 循环

修复类任务的标准工作流：**审查 → 修复 → 验证 → 再审查**，循环直到没有新问题。

## 何时使用

- 用户要求"修一下 X"、"review 后修复"、"把这些问题都处理掉"
- 涉及代码改动，需要保证质量收敛
- 发版前的最后质量把关

## 工作流

```text
第 1 步 审查：对改动/目标代码做多角度审查（正确性/并发/错误恢复/边界），
        列出问题（按严重度排序，附文件:行号证据）
第 2 步 修复：按严重度逐个修复（小步改动，保持可编译）
第 3 步 验证：跑测试/构建/复现，确认修复真实生效
第 4 步 再审查：对修复后的代码重新审查，找新问题
→ 有新问题 → 回到第 2 步
→ 无新问题 → 完成
```

## 循环规则

- **收敛标准**：连续一轮审查无新问题（或只剩已知边界/低优先项）
- **每轮进度**：向用户简短汇报（本轮发现 X 个问题 → 修复 Y 个 → 验证结果），不重复细节
- **失败不掩盖**：测试失败如实报告，不因"修完了"跳过验证
- **成本控制**：问题收敛到零或只剩风格级时停止，不做无限优化

## 输出

最终结论：审查轮数、修复问题数、验证结果、剩余已知边界。
